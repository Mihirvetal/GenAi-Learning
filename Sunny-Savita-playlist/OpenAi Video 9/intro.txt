1. Temperature (Randomness)Temperature controls the randomness of the model's output token selection. Think of it as a "creativity" slider.Range: Typically 0.0 to 2.0Low Temperature (e.g., 0.1 to 0.3): The model becomes deterministic and focused. It will almost always choose the most highly probable next words. Best for: Coding, math, data extraction, and factual Q&A.High Temperature (e.g., 0.7 to 1.2): The model takes more risks, choosing less expected words. Best for: Creative writing, brainstorming, and roleplay.2. Top-P (Nucleus Sampling)Top-P changes how the model selects words based on their cumulative probability.Range: 0.0 to 1.0How it works: If you set top_p=0.9, the model looks at the pool of most likely next words and cuts off the bottom pool, keeping only the top words whose percentages add up to 90%. It then selects from only that group.Impact: Decreasing Top-P filters out the "long tail" of low-probability words, preventing the model from generating random gibberish or completely off-topic phrases.3. Top-KTop-K sets a strict limit on the absolute number of highest-probability words the model can choose from for its next token.Range: 1 to 500+ (or set to 0/unset to disable)How it works: If you set top_k=3, the model will only consider the top 3 absolute most likely words for the next token, discarding everything else regardless of how high their probability scores are.Impact: A low Top-K keeps the output highly safe and predictable, while a higher Top-K allows for more diverse vocabulary.4. Max Output TokensThis sets a hard ceiling on the length of the model's response.How it works: One token is roughly equal to 4 characters or 0.75 words.Impact: If you are building a chat application and want to save on API costs or prevent the model from writing long essays, you can restrict this (e.g., max_output_tokens=150).How to use them in the New SDKIn the new google.genai SDK, you import types from the library and build a configuration object to pass directly into your generation request.Here is a complete, working example showing how to configure these parameters in your Colab notebook:Pythonfrom google import genai
from google.genai import types

# 1. Initialize your client
client = genai.Client(api_key="YOUR_GOOGLE_API_KEY")

# 2. Define your configuration parameters
creative_config = types.GenerateContentConfig(
    temperature=0.9,       # Highly creative and expressive
    top_p=0.95,            # Consider a wide pool of probable words
    top_k=40,              # Choose from the top 40 words at each step
    max_output_tokens=300  # Restrict response length to roughly 225 words
)

# 3. Pass the config object into your request
response = client.models.generate_content(
    model='gemini-2.5-flash',
    contents='Write an unusual metaphor describing a software bug.',
    config=creative_config # <--- Pass it right here
)

print(response.text)

Embeddings: 
1. What Exactly is an Embedding?Computers don't understand words, emotions, or concepts; they only understand numbers.An embedding is a technique that takes a piece of data (like a word, a sentence, or even an image) and translates it into a long list of numbers, called a vector.  But it’s not just any random list of numbers. These numbers represent coordinates in a massive, multi-dimensional "semantic space" (often hundreds or thousands of dimensions wide).  The Golden Rule of Embeddings: Words or sentences that share a similar meaning are placed close together in this mathematical space. Words that are completely unrelated are placed far apart.2. The Classic Analogy: The "Concept Map"Imagine a giant 3D room where we are hanging words in mid-air based on their characteristics:"King" and "Queen" would float very close to each other because they both represent royalty and humans."Apple" and "Banana" would float together in a completely different corner (the fruit section)."Apple" (the fruit) and "Apple" (the tech company) might sit somewhere in between, pulling toward both electronics and food depending on the context!Because these words have coordinates, we can actually do math on human language. The famous machine learning equation looks like this:$$\text{Vector("King")} - \text{Vector("Man")} + \text{Vector("Woman")} = \text{Vector("Queen")}$$If you subtract the concept of "male" from King, and add the concept of "female", the closest mathematical coordinate in the embedding space lands right on the word Queen.3. Why Do We Need Them in GenAI? (The "Why")Without embeddings, computers only match words exactly. If you search a document for "dog", a basic search engine won't find a sentence that says "The golden retriever barked," because the word "dog" isn't explicitly there.Because an embedding model converts both into vectors, it realizes that "golden retriever" and "dog" are mathematically very close. This enables:Semantic Search: Searching by intent and meaning, not just exact keywords.  RAG (Retrieval-Augmented Generation): Converting your company's PDFs into vectors so an AI can quickly pull the most relevant paragraphs to answer a user's question.Recommendation Systems: Finding movies or products whose descriptions have similar vector representations to things you've liked before.4. What Does the Code Look Like?Since you are following Sunny’s playlist, you’ll likely use Google’s embedding models (gemini-embedding-001). Here is a quick look at how you generate these numbers in the modern SDK:Pythonfrom google import genai

client = genai.Client()

# Generate the embedding vector
response = client.models.embed_content(
    model="gemini-embedding-001",
    contents="What is Retrieval-Augmented Generation?"
)

# This will print a massive list of numbers (usually 768 to 3,072 numbers long!)
print(response.embeddings[0].values)
Each number in that giant list represents a specific "feature" or "trait" of the text that the AI figured out during its training, allowing it to understand context deeper than any dictionary ever could.To see this workflow in a real-world scenario, you can check out this Talk to documents with embeddings guide which explains how Google's native embedding models organize text, images, and documents into a unified vector space.


1. Concrete Example: What an Embedding Actually Looks LikeImagine we have three simple sentences:"I love coding in Python.""Writing software is my passion.""The weather is very sunny today."If we pass these sentences through an embedding model, it converts each sentence into a vector (a list of numbers). To keep this example simple, let's pretend our model only outputs 3 numbers (3 dimensions) instead of the thousands it usually does:SentenceEmbedding Vector (Simplified)S1: "I love coding in Python."[0.92, 0.88, 0.12]S2: "Writing software is my passion."[0.89, 0.85, 0.15]S3: "The weather is very sunny today."[0.05, 0.11, 0.95]The Logic Behind the Numbers:Look at the first two numbers in the vectors for S1 and S2. They are highly similar (0.92 vs 0.89 and 0.88 vs 0.85). Why? Because the model recognizes that "coding", "Python", "writing software", and "passion" are all tightly related to the concept of programming.Now look at S3. Its numbers are completely different because "weather" and "sunny" have zero semantic relationship to software development.2. A Practical Real-World Example: Building a Smart Job SearchLet's say you are building a recruitment feature for a job portal. A candidate uploads their resume, and you want to match them to the right job openings—even if they didn't use the exact same keywords.The Problem with Traditional Keyword Search:Candidate's Resume says: "Experienced in building full-stack web applications using React and Node.js."Job Posting A says: "Looking for a MERN developer to scale our platform."Job Posting B says: "Hiring a manual QA engineer for testing web layouts."If you use a basic keyword match (like SQL or Ctrl+F), Job Posting A might get rejected because the words "full-stack", "React", and "Node" do not explicitly match the word "MERN" (MongoDB, Express, React, Node).The Solution using Embeddings:By implementing an embedding workflow, the search becomes instantly intelligent:Pythonfrom google import genai
import numpy as np

client = genai.Client()

# 1. Generate embeddings for the resume and the job listings
resume_emb = client.models.embed_content(
    model="gemini-embedding-001",
    contents="Experienced in building full-stack web applications using React and Node.js."
).embeddings[0].values

job_a_emb = client.models.embed_content(
    model="gemini-embedding-001",
    contents="Looking for a MERN developer to scale our platform."
).embeddings[0].values

job_b_emb = client.models.embed_content(
    model="gemini-embedding-001",
    contents="Hiring a manual QA engineer for testing web layouts."
).embeddings[0].values

# 2. Mathematical comparison helper (Cosine Similarity)
def calculate_similarity(v1, v2):
    return np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))

# 3. Compare the resume against both jobs
match_score_a = calculate_similarity(resume_emb, job_a_emb)
match_score_b = calculate_similarity(resume_emb, job_b_emb)

print(f"Match score with Job A (MERN Developer): {match_score_a:.4f}")
print(f"Match score with Job B (QA Engineer):   {match_score_b:.4f}")
The Expected Result:Match score with Job A: ~0.88 (Very High Similarity)Match score with Job B: ~0.42 (Low Similarity)Even though the candidate never wrote the word "MERN" on their resume, the embedding model already knows from its training that React + Node.js sits in almost the exact same mathematical neighborhood as MERN.This mathematical comparison is the foundational engine behind RAG (Retrieval-Augmented Generation), semantic search bars, and recommendation engines.



Safety Settings

Google’s GenAI SDK allows you to configure thresholds across specific harm categories. If a prompt or response violates your thresholds, the API blocks it automatically.  1. The 4 Main Harm CategoriesGemini monitors every single input and output across four primary categories:  HARM_CATEGORY_HARASSMENT: Content that targets individuals or groups with malicious, derogatory, or bullying language.  HARM_CATEGORY_HATE_SPEECH: Content that promotes discrimination, disparagement, or violence against protected groups (based on race, religion, gender, etc.).  HARM_CATEGORY_SEXUALLY_EXPLICIT: Contains graphic, lewd, or highly suggestive sexual content.  HARM_CATEGORY_DANGEROUS_CONTENT: Content that promotes, facilitates, or gives actionable instructions on how to perform illegal or self-harming acts (e.g., "how to build a weapon" or "how to hack a server").  2. The 4 Blocking ThresholdsFor each category above, you get to decide how strict you want to be based on the probability or severity of the harm:Threshold SettingWhat it doesBest Use CaseBLOCK_LOW_AND_ABOVESuper Strict. Blocks content even if there is only a slight chance it might be harmful.Public-facing customer service chatbots, kids' apps.BLOCK_MEDIUM_AND_ABOVEBalanced (Default). Blocks content with a medium or high probability of being harmful.General corporate tools, standard productivity apps.BLOCK_ONLY_HIGHPermissive. Only blocks content when it is unmistakably and highly harmful.Creative writing assistants, academic research tools.BLOCK_NONENo Filter. Disables automated blocking entirely for that category.Highly restricted setting (often requires special cloud permissions).3. Practical Code Example (Using the New SDK)Let's see how to write a Python script that sets up a strict configuration for a customer-facing app, and how to handle the response if a user tries to trigger a block.Pythonfrom google import genai
from google.genai import types

client = genai.Client()

# 1. Define your custom safety settings
custom_safety = [
    types.SafetySetting(
        category="HARM_CATEGORY_HARASSMENT",
        threshold="BLOCK_LOW_AND_ABOVE" # Very strict against bullying
    ),
    types.SafetySetting(
        category="HARM_CATEGORY_DANGEROUS_CONTENT",
        threshold="BLOCK_MEDIUM_AND_ABOVE" # Balanced protection against dangerous stuff
    )
]

# 2. Bundle it inside the generation configuration
config = types.GenerateContentConfig(
    safety_settings=custom_safety,
    temperature=0.7
)

try:
    # 3. Call the model with your custom config
    # (Pretend an angry user inputted a toxic prompt here)
    response = client.models.generate_content(
        model="gemini-2.5-flash",
        contents="Write a highly offensive and mean insult targeting my coworker.",
        config=config
    )
    
    # 4. Check if the model actually generated text or got blocked
    if response.candidates and response.candidates[0].finish_reason.name == "SAFETY":
        print("Fallback System Message: I cannot generate derogatory content.")
    else:
        print("Model Response:", response.text)

except Exception as e:
    print(f"An error occurred: {e}")
4. Behind the Scenes: What a "Blocked" Response Looks LikeWhen the safety filter triggers, the API doesn't just crash. It returns a metadata-rich object. If you inspected response.candidates[0], you would see something like this:JSON{
  "finish_reason": "SAFETY",
  "safety_ratings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "probability": "HIGH",
      "blocked": true
    },
    {
      "category": "HARM_CATEGORY_DANGEROUS_CONTENT",
      "probability": "NEGLIGIBLE",
      "blocked": false
    }
  ]
}
Because finish_reason is explicitly flagged as "SAFETY", the response.text field will technically be completely empty. As a software engineer, your job is to check for that finish_reason in your backend code and return a clean, friendly fallback message to the user (like "I can't help with that request"), ensuring your UI never breaks.
